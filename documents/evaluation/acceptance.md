# Приёмка текущего прототипа

31 октября 2026 года. Проверяемая версия: `9565daa5a28edd0d6b1507f981dc6ee51004af85`.

Сохранённые автоматические проверки применимы к текущей версии. Два новых программных прохода с учебной моделью завершились успешно. **Раздел 6 пока не закрыт: два прохода человеком через экран не подтверждены.** Проверка интерфейса ассистентом также не выполнена из-за недоступности средства управления браузером.

Код приложения не менялся. Платных запросов и новых сравнительных серий не было; исходные данные τ-bench сохранены.

## Применимость результатов

В [сводке проверки](../../evals/acceptance/2026-10-31/validation.json) сохранены текущие хеши и результаты сверки:

- 24 файла тестов побайтово совпадают с сохранённой рабочей копией, на которой выполнены 206 проверок; сохранённый XML совпадает с результатом той копии;

В [предыдущем XML](../../evals/reapproval/2026-10-31/pytest-after-fix.xml) — 206 успешных проверок, без ошибок и пропусков. Полный `pytest` повторно не запускался: поведение и тесты не менялись. Это использование подтверждённого результата, а не новый прогон.

## Что дополнительно проверено сейчас

Через `create_service` и настоящий `DemoModel` выполнены два программных сценария в режиме `manual`, каждый на отдельной SQLite. [Скрипт](../../evals/acceptance/2026-10-31/check_demo_flow.py) и [результаты](../../evals/acceptance/2026-10-31/service-flows/results.json) сохранены. Это новые проверки соединённых компонентов без UI и API.

| Сценарий | Фактический результат |
|---|---|
| Обычный обмен | Одна заявка `exchange requested`, разница 2,35 USD, два подтверждения сотрудника, одно согласие клиента и две доставки |
| Цена замены изменилась с 12,35 до 19,99 USD после согласия клиента | Старая версия заблокирована; после ручного продолжения получены новые согласования. Одна заявка с разницей 9,99 USD, три подтверждения сотрудника, два согласия клиента и три доставки |

В обоих сценариях итоговый доставленный текст совпал с подтверждённым. Реальных списаний, возвратов денег или писем нет. Новые состояния не переносились между сценариями.

Два временных сервера Streamlit на портах 8503 и 8504 вернули `200 ok` на проверку доступности и были остановлены. Доступ через браузерную среду отсутствовал, а запрос управления нативным Chrome завершился по тайм-ауту. Поэтому экран в этой приёмке не пройден ни ассистентом, ни человеком. Старые результаты `AppTest` сохранены; заново они не запускались.

## Два сценария ручной приёмки

Оба прохода пока **не выполнены человеком**. Команды ниже используют синтетический магазин, учебную модель и тестовый канал; ключи и API не нужны. Нужное окружение уже установлено. Выполнять из корня `ai-support-agent`.

### Подготовка

```powershell
$env:SUPPORT_AGENT_MODE = 'demo'
$env:SUPPORT_AGENT_RECOVERY_MODE = 'manual'
$env:SUPPORT_AGENT_RETAIL_DB = 'evals/reapproval/base_shop.json'
$env:SUPPORT_AGENT_DB = 'var/acceptance-user-normal.sqlite3'
if (Test-Path -LiteralPath $env:SUPPORT_AGENT_DB) { throw 'Выберите новое имя базы, сохранив предыдущую историю.' }
..\tau2-bench\.venv\Scripts\python.exe -m streamlit run src/support_agent/ui.py --server.address 127.0.0.1 --server.port 8503 --server.headless true --browser.gatherUsageStats false
```

Открыть `http://127.0.0.1:8503`. Проверить, что экран сообщает об учебном режиме. В конце прохода остановить сервер `Ctrl+C`. Если имя базы заменено, использовать это же имя в команде изменения цены ниже.

### 1. Обычный обмен

1. Выбрать клиента `user1@example.test`, нажать «Новое обращение». Ввести: «Обменяйте товар на любой другой доступный вариант. Email user1@example.test» и нажать «Подготовить решение».
2. Проверить основания, заказ `#O1`, замену `old` на `new`, карту `card`, доплату **2,35 USD** и точный текст. До подтверждения сообщение не доставлено, заявки нет.
3. Подтвердить отправку условий. В тестовом канале ввести «Согласен на обмен и доплату 2.35 USD» и нажать «Клиент согласен». Проверить карточку «Действие и ответ»: заявка ещё не создана.
4. Подтвердить действие и ответ. Ожидается одна заявка `exchange requested`, согласованный ответ в тестовом канале, две доставки за весь проход: условия и итог. Деньги и внешние письма отсутствуют.
5. Обновить страницу, выбрать сохранённое обращение. Результат и история сохраняются, новой операции и повторной доставки нет.

### 2. Изменение цены и новое согласование

После остановки первого сервера установить `$env:SUPPORT_AGENT_DB = 'var/acceptance-user-price.sqlite3'`, проверить отсутствие файла через `Test-Path` и повторить команду запуска из подготовки. Остальные настройки прежние. Новая база восстанавливает исходные данные, не меняя историю первого прохода.

1. Повторить шаги 1–3 обычного обмена. Остановиться на карточке «Действие и ответ» после согласия клиента на **2,35 USD**, до подтверждения сотрудником.
2. Во втором терминале из корня проекта выполнить команду ниже. Она меняет только цену в отдельной рабочей базе приёмки; исходный JSON не изменяется.

```powershell
@'
from pathlib import Path
from support_agent.storage import Store
p = Path('var/acceptance-user-price.sqlite3')
assert p.is_file(), 'Acceptance database not found'
store = Store(p)
with store.transaction() as conn:
    assert conn.execute('SELECT COUNT(*) FROM cases').fetchone()[0] == 1
    assert conn.execute('SELECT COUNT(*) FROM operations').fetchone()[0] == 0
    assert conn.execute('SELECT COUNT(*) FROM consents WHERE accepted=1 AND revoked=0').fetchone()[0] == 1
    data, _ = store.retail(conn)
    assert data['orders']['#O1']['status'] == 'delivered'
    variant = data['products']['p1']['variants']['new']
    assert variant['price'] == 12.35
    variant['price'] = 19.99
    store.save_retail(conn, data)
print('Price changed: 12.35 -> 19.99 USD')
'@ | ..\tau2-bench\.venv\Scripts\python.exe -
```

3. На прежней карточке нажать подтверждение. Ожидается блокировка устаревшего решения; заявки и итогового сообщения нет. Нажать «Продолжить расследование».
4. Проверить новые условия с доплатой **9,99 USD**. Подтвердить их отправку, ввести «Согласен на новые условия и доплату 9.99 USD», нажать «Клиент согласен». Затем отдельно подтвердить обновлённое действие и ответ.
5. Ожидается одна заявка на новых условиях и три доставки: старые условия, новые условия, итог. В журнале есть блокировка и ручное продолжение. После обновления страницы операция и сообщения не повторяются. В режиме `manual` подробная таблица «было / стало» не требуется: проверяются причина блокировки и новая сумма в карточке.

Для каждого сценария записать в эту сводку дату, версию приложения, режимы `demo`/`manual`, фактический результат и замечания. Сообщить, видны ли основания, сумма, точный текст и результат; при ошибке указать шаг. До получения этих результатов статус человеческой приёмки остаётся открытым.
