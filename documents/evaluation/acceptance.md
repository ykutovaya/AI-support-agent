# Приёмка retail-версии

**2 ноября 2026 года:** оба сценария обмена пройдены пользователем на версии `015507267c91e893203fdf1c81c041401550a250`, в режимах `demo/manual`. Базовая retail-версия принята по этим сценариям. Проверка пункта 1-а для текущей рабочей копии использует обычный Streamlit CLI и закреплённую версию 1.56.0; результаты приведены ниже. Исходная версия ручных проходов и их результаты сохранены.

## Два сценария ручной приёмки

Проверялся синтетический магазин: клиент `u1`, заказ `#O1`, замена `old → new`, карта `card`. Для каждого сценария использована отдельная SQLite. Условия и точный текст подтверждает сотрудник; согласие клиента учитывается отдельно. Запуск — по [README](../../README.md#запуск-рабочего-места).

| Сценарий | Ожидаемый и фактический результат |
|---|---|
| Обычный обмен | Доплата **2,35 USD**, одна заявка `exchange requested`, два подтверждения сотрудника, одно согласие клиента и две доставки: условия и итог |
| Изменение цены после согласия клиента | Цена замены **12,35 → 19,99 USD**. Старое решение заблокировано; после ручного продолжения получены новые согласования. Доплата **9,99 USD**, одна заявка, три подтверждения сотрудника, два согласия клиента и три доставки: прежние условия, новые условия и итог |

Действия через экран выполнял пользователь с подсказками ассистента. Пользователь подтвердил сохранение сообщений после обновления страницы и перезапуска. Ассистент настроил запуск, изменил цену в учебном снимке и проверил SQLite: повторных операций и доставок нет. В сценарии изменения цены содержимое всех таблиц до и после перезапуска совпало. Идентификаторы обращений, локальные базы и результаты сверки сохранены в [записи ручной приёмки](../../evals/acceptance/2026-11-02/human-acceptance.json).

## Остановка Windows

Обычная команда `python -m streamlit run src/support_agent/ui.py` сохранена. В зависимостях закреплён Streamlit 1.56.0: он сам выбирает Selector на Windows до запуска сервера. В Python 3.12.12 ошибка `socket.shutdown` с кодом `10054` может пропустить очистку соединения Proactor, после чего сервер продолжает ждать.

Падающая проверка обычного CLI с Streamlit 1.66.0 воспроизвела этот путь управляемой инъекцией ошибки. Результат для 1.56.0: остановка с открытой сессией — **1.532 с**, остановка после повторного запуска с той же SQLite — **1.437 с**. Порт и процессы тестового сервера закрыты без принудительного завершения; сохранены одна операция и две доставки. Текущая проверка — **207 тестов без API**: 195 прошли сразу, 12 — после добавления недостающих файлов стенда в проверочную копию. Первоначальный отчёт с этими техническими ошибками сохранён. [Настройки, журналы и результаты](../../evals/shutdown/2026-11-02-native/summary.json).

Проверку выполняет ассистент через настоящий `CTRL_C_EVENT` в отдельной скрытой консоли PowerShell и программный WebSocket-клиент. Физическое нажатие клавиш человеком не повторялось. Естественный TCP RST сам по себе исходную ошибку не воспроизвёл; инъекция проверяет конкретный путь из пользовательского traceback. Это не проверка всех возможных причин зависания.

Прежний обход через `support_agent.launcher`, его 15 успешных тестов и времена остановки сохранены как [исторический результат](../../evals/shutdown/2026-11-02/summary.json). Он не является текущим способом запуска; прежние отчёты и ручная приёмка не переписаны.

Проверена локальная конфигурация `127.0.0.1`. Selector ограничен 512 сокетами и не поддерживает асинхронные subprocess/pipes. Streamlit 1.56.0 не содержит дополнительных защит, появившихся в 1.60; сетевую публикацию не проверяли. Подробности и первичные источники — в [архитектуре](../architecture.md#остановка-локального-сервера).

Рабочее окружение обновлено до проверенных версий. τ-bench установлен из локальной копии того же чистого закреплённого коммита; установленные Python-файлы сверены с исходниками. Сервер на порту 8504 восстановлен с прежней базой. Содержимое обеих баз ручной приёмки до и после обновления совпадает. [Сверка окружения и истории](../../evals/shutdown/2026-11-02-native/runtime-update.json).

## Оставшиеся ограничения

- **Удобство экрана:** приёмка потребовала подсказок; список обращений и вывод события об изменении условий были непонятны. Это не проверка самостоятельной работы сотрудника.
- **Оценщик:** ошибка распознавания корректного отказа остаётся задачей перед новым сравнением. Оценки первого пилота **5/6** и основного прогона **17/18** не менялись; разбор — в [отчёте](reapproval.md).
- **Границы результата:** `DemoModel` и ручное продолжение проверяют процесс, не качество языковой модели. Регистрируется заявка на обмен; деньги не списываются и не возвращаются, письмо не отправляется. Канал сообщений локальный и тестовый. API и новые сравнительные серии не запускались; исходные данные τ-bench не изменялись.
