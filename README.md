# ИИ-агент поддержки

[Презентация проекта](https://drive.google.com/file/d/1AypVN3gY3T7rxMVN6cjpJVDXuc3Mq-FW/view?usp=sharing)

Агент разбирает обращения об обмене и возврате товаров: читает данные, проверяет правила и готовит решение. Сотрудник видит основания, параметры и точный ответ клиенту. После подтверждения приложение выполняет действие, проверяет результат и сохраняет историю.

- **Подтверждение конкретных условий.** Если доплата выросла с 2,35 до 9,99 USD, старое решение блокируется. Новые условия требуют нового согласия клиента и подтверждения сотрудника. [Пример](documents/evaluation/acceptance.md#2-изменение-цены).
- **Проверка результата перед ответом.** Сотрудник видит действие в магазине, заявку специалисту, согласованный текст и доставку. [Как устроена проверка](documents/architecture.md#прохождение-обращения).
- **Восстановление без повторной записи.** При неизвестном исходе Zammad повторное создание блокируется до проверки результата. [Испытание потерянного ответа](documents/evaluation/zammad-integration.md#настоящий-api).

Портфельный прототип использует синтетический магазин в формате `retail` τ-bench. Основной режим `demo/manual/local` работает без ключей: ответы модели заданы заранее, продолжение после смены условий запускает сотрудник, заявки хранятся в SQLite. Настоящая модель (`api`) и Zammad включаются отдельно. Агент может подготовить передачу нерешённого вопроса специалисту с фактами, правилом и выполненными проверками.

## Запуск рабочего места

Нужны Windows, Git и uv 0.10.4. Проверенная версия Python — 3.12.12, Streamlit — 1.56.0. Команды PowerShell выполняйте из корня проекта.

Установка в отдельное окружение `var/runtime`:

```powershell
$env:UV_PROJECT_ENVIRONMENT = 'var/runtime'
uv sync --locked --extra retail --extra dev --python 3.12.12
```

Первая установка требует интернета: зависимости закреплены в `uv.lock`, τ-bench — на конкретном commit. Существующие `.venv` приложения и соседнего τ-bench не переустанавливаются. Повторный `uv sync` обновляет только выбранное окружение; для проверки установки с нуля используйте новый каталог окружения.

Запуск учебного рабочего места без API:

```powershell
$env:SUPPORT_AGENT_MODE = 'demo'
$env:SUPPORT_AGENT_RECOVERY_MODE = 'manual'
$env:SUPPORT_AGENT_TICKET_BACKEND = 'local'
$env:SUPPORT_AGENT_RETAIL_DB = 'evals/reapproval/base_shop.json'
$env:SUPPORT_AGENT_DB = 'var/demo.sqlite3'
.\var\runtime\Scripts\python.exe -m streamlit run src/support_agent/ui.py --server.address 127.0.0.1 --server.port 8501 --server.headless true --browser.gatherUsageStats false
```

Откройте **[http://127.0.0.1:8501](http://127.0.0.1:8501)**. Для остановки нажмите `Ctrl+C` в терминале. Повторный запуск с той же базой сохраняет историю.

Для первого обращения выберите `user1@example.test`, нажмите «Новое обращение» и введите: **«Обменяйте товар. Email user1@example.test»**. Дальнейшие действия — в [руководстве](documents/usage.md#обмен-и-возврат). Для трёх готовых сценариев используйте отдельную базу из [инструкции приёмки](documents/evaluation/acceptance.md).

## Результаты

| Что проверено | Результат и подробности |
|---|---|
| Работа сотрудника | Обмен, изменение цены и локальная передача пройдены без подсказок. История сохраняется после обновления и перезапуска. [Приёмка](documents/evaluation/acceptance.md#результаты-и-границы-проверки) |
| Расследование с настоящей моделью | Исходный контроль — **4/6**. Отдельный новый набор — **4/6**, завершённые обращения прошли без исправлений сотрудника. Два корректных текста оценщик остановил до доставки (`review`). Наборы не являются прямым сравнением версий. [Отчёт](documents/evaluation/investigation.md#шесть-новых-обращений--отдельный-контроль) |
| Настоящий Zammad | Создание заявки и восстановление после потери ответа: по одному POST и одной доставке. Программная проверка с учебной моделью. [Отчёт](documents/evaluation/zammad-integration.md) |

Принятие предложения без правок и правильность результата измеряются отдельно. Результаты небольших учебных наборов не подтверждают CSAT, SLA или окупаемость.

После исправления оценщика оба остановившихся случая завершены на заданных ответах без API. Это проверка процесса, исходные **4/6** не изменены. [Техническая проверка](documents/evaluation/investigation.md#итоговая-техническая-проверка-без-api).

## Проверки

В установленном окружении:

```powershell
.\var\runtime\Scripts\python.exe -m pytest
.\var\runtime\Scripts\python.exe -m ruff check .
```

[GitHub Actions](.github/workflows/checks.yml) запускает pytest и Ruff при `push` и `pull_request`, без ключей модели и Zammad. Команды испытаний, пример ядра и сохранённые результаты — в [evals/README.md](evals/README.md).

## Ограничения

Обмен и возврат регистрируют запросы; реальные выплаты и отправка товара не выполняются. Ответы сохраняются в тестовом канале, письма не отправляются. Создание заявки специалисту не означает решение вопроса.

Настоящие CRM и авторизация сотрудников не подключены. Учебная модель не разбирает произвольные предпочтения. Проверен локальный запуск на `127.0.0.1`; режим с внешним API модели не является закрытым контуром. Автоматическое продолжение после смены условий остаётся экспериментальным и не заменяет согласования.
