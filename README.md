# ИИ-агент поддержки

Общее ядро расследования работает через адаптер τ-bench и из отдельного примера приложения. Ядро получает сообщения, правила и схемы инструментов; возвращает проект ответа или запрос действия и новое состояние диалога.

В приложении запись и отправка клиенту пока отсутствуют. Экран сотрудника, согласования, постоянное хранилище и исполнитель относятся к следующим этапам. В штатном τ-bench инструменты выполняет сама испытательная среда; подтверждение сотрудника туда не добавляется.

## Запуск без API

Нужны Python 3.12 и uv. Команды PowerShell из корня проекта:

```powershell
uv sync --locked --extra dev
uv run python -m support_agent.demo
uv run --extra dev pytest
```

Пример использует синтетический заказ и заранее заданные ответы модели. Он показывает чтение и предложение отмены, но ничего не отменяет и не отправляет. Это проверка подключения общего ядра, а не демонстрация качества модели. Ключи и τ-bench для него не нужны.

Проверки адаптера и запуска оценки пропускаются, если `tau2` не установлен. Остальные проверки работают самостоятельно.

## Модель и состояние

`AgentCore(model=..., policy=..., tools=..., language="ru")` принимает любой адаптер с методом `generate(messages, tools)`. Для API используется `LiteLLMClient(model, llm_args)`. Имя модели, параметры и язык передаются при создании компонентов; настройки не зашиты в ядро.

`init_state()` создаёт независимое обращение. `step(incoming, state)` возвращает `Generation` и новое `AgentState`, не меняя переданное состояние. После запроса инструментов вызывающая сторона передаёт результаты с теми же идентификаторами. Ошибка и отклонение инструмента сохраняются. Состояние можно сериализовать через `model_dump_json()`; постоянного хранилища ещё нет.

Ядро проверяет имя инструмента и JSON Schema аргументов. Это не заменяет будущие проверки прав, принадлежности данных, сумм и согласований. Только вызывающая сторона решает, можно ли исполнить предложенное действие или отправить ответ.

## τ-bench и контроль задачи 75

Используется соседний репозиторий [tau2-bench](https://github.com/sierra-research/tau2-bench), commit `da0835f6c67baef58bdda18f2a3b037dfb3a1754`. Исходные `db.json`, задания, правила и инструменты не копируются и не изменяются.

Для установки проекта и проверок в уже подготовленное окружение τ-bench:

```powershell
uv pip install --python ..\tau2-bench\.venv\Scripts\python.exe -e ".[dev]"
$env:TAU2_DATA_DIR = (Resolve-Path ..\tau2-bench\data).Path
..\tau2-bench\.venv\Scripts\python.exe -m pytest
```

Сухая проверка сверяет настройки, commit и исходные файлы с исходной оценкой. Она не читает `.env`, не создаёт каталог результатов и не вызывает API:

```powershell
..\tau2-bench\.venv\Scripts\python.exe evals\core-integration\run_control.py --repo ..\tau2-bench --dry-run
```

Для оплачиваемого прогона нужен `OPENAI_API_KEY` в `..\tau2-bench\.env` или переменных процесса; пример настроек — [.env.example](.env.example). Скрипт фиксирует модель `openai/responses/gpt-6-luna` и параметры исходной оценки. Он выполняет одну попытку задачи 75 и требует новый каталог:

```powershell
..\tau2-bench\.venv\Scripts\python.exe evals\core-integration\run_control.py --repo ..\tau2-bench --run --run-dir evals\core-integration\new-attempt
```

Повтор успешного прогона нужен только после значимого изменения. Регистрация адаптера выполняется внутри процесса, поэтому `workers=0`. Условия задачи и скрытые инструкции имитатора исключены из фабрики ядра. Полные результаты могут содержать критерии для последующего разбора — это не контекст агента.

В Windows скрипт временно добавляет доверенные системные центры сертификации к certifi. Проверка TLS остаётся включённой. Ключи не входят в параметры модели и удаляются из сохраняемых текстовых артефактов.

## Файлы

| Путь | Назначение |
|---|---|
| `src/support_agent/models.py` | Собственные сообщения, инструменты, состояние и результат модели |
| `src/support_agent/agent.py` | Один шаг общего ядра без исполнения действий |
| `src/support_agent/adapters/llm.py` | Обращение к модели через LiteLLM |
| `src/support_agent/adapters/tau_bench.py` | `HalfDuplexAgent`, преобразование сообщений и регистрация |
| `src/support_agent/demo.py` | Независимый пример без API |
| `tests/` | Проверки контрактов, диалога, адаптеров и запуска |
| `evals/core-integration/` | Скрипт и результаты контрольного прогона |

Версии прямых зависимостей закреплены в `pyproject.toml`, полный набор — в `uv.lock`. Установка в отдельное окружение проверена. τ-bench распространяется под MIT; условия заимствованной инструкции приведены в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). Данные примера синтетические. Публичные данные τ-bench не подтверждают готовность к работе с реальной CRM.
