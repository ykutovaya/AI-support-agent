# Проверка пересогласования

Это собственные синтетические испытания приложения. Они не входят в τ-bench.
Клиент и сотрудник следуют заранее заданному сценарию; их удобство и время работы
здесь не измеряются. Используются настоящее ядро, SQLite и RetailTools.

## Без API

```powershell
python evals/reapproval/run_reapproval.py --offline --run-dir C:/Temp/reapproval-offline
```

Каталог должен быть новым. Проверка выполняет шесть проходов с программной
заглушкой и сохраняет `offline/manifest.json`. Это проверка проводки, не пилот и
не доказательство преимущества языковой модели.

## Оплачиваемое сравнение

```powershell
python evals/reapproval/run_reapproval.py --run --phase pilot --budget-usd 5 --repo C:/Users/USER/Documents/portfolio/tau2-bench --run-dir C:/Temp/reapproval-live
python evals/reapproval/run_reapproval.py --run --phase main --budget-usd 5 --repo C:/Users/USER/Documents/portfolio/tau2-bench --run-dir C:/Temp/reapproval-live
```

Вторую команду запускают после разбора пилота: измерение должно работать, гипотеза
оставаться осмысленной, бюджет — достаточным. Положительный эффект пилота не
является условием продолжения. Команда основного прогона проверяет техническую
готовность пилота и неизменность кода, данных и настроек. Без этого она остановится.

`budget.json` общий для подготовки, шести пилотных и восемнадцати основных попыток.
Не создавайте новый каталог для обхода лимита. Ключи читаются из `.env` соседнего
τ-bench только при `--run`, не передаются в параметры модели и не сохраняются.
Имитация клиента и сотрудника не вызывает API; отдельного оценщика нет.

Модель — `openai/responses/gpt-6-luna`, `reasoning_effort=low`, `max_tokens=8192`,
тайм-аут запроса до 90 секунд, повторов API и целой попытки нет. На всю попытку,
включая повторную подготовку, допускаются 60 шагов и 600 секунд. Шаг — вызов модели,
запрошенный ею инструмент или действие имитируемого сотрудника.

До каждого запроса в журнал записывается резерв: размер полного запроса в байтах
UTF-8 плюс 8192 токена на обрамление, полный допустимый выход и более дорогой тариф
длинного контекста. Тарифы закреплены по
[странице модели](https://developers.openai.com/api/docs/models/gpt-6-luna),
проверенной 31 октября 2026 года: $0,10/$0,50 за миллион входных/выходных токенов;
для входа свыше 272 тысяч токенов множители 2/1,5. Кеш не уменьшает оценку.
После ответа учитывается большая из оценки по usage и сообщённой стоимости.
При неизвестном расходе или ошибке весь резерв остаётся израсходованным. Если
остатка недостаточно, запроса не будет. Неизвестная модель блокируется.
Это ограничение запросов по закреплённым тарифам, не лимит биллинга провайдера.

## Случаи и результат

Пилотные и основные случаи закреплены в `scenarios.json` и различаются заказами,
клиентами, товарами и суммами. Основа `base_shop.json` взята из собственного
`tests/retail_data.py`; данные синтетические, скрытые критерии τ-bench не используются.

Для каждого случая модель готовит начальное предложение. Сотрудник проверяет
точные позиции, карту и сумму, подтверждает отправку условий; клиент соглашается.
Полученный SQLite-файл — общая контрольная точка двух режимов перед окончательным
подтверждением сотрудника. В каждой попытке создаётся новая копия всего файла.

После контрольной точки цена меняется, статус становится `cancelled` либо ничего
не меняется. В обоих режимах старое действие одинаково проверяет исполнитель.
Ручной режим требует `resume`, автоматический готовит новую версию сам. Новые
условия по-прежнему требуют согласия клиента и двух подтверждений сотрудника:
отправки вопроса и исполнения с итоговым ответом.

Сотрудник не соглашается на другой заказ, позиции, карту или сумму. При отменённом
заказе правильный результат — отсутствие операции и доставленное объяснение.
Проверка текста механическая: нужен отменённый статус и невозможность обмена,
без нового вопроса и утверждения об исполнении. Неожиданный ответ сохраняется
как неуспех, а не исправляется по результатам измерения.

В `manifest.json` находятся условия, хеши, расходы, результаты и парные разницы.
В каталогах попыток — сообщения модели, события, состояние SQLite и JSON.
Дополнительные вмешательства — `manual_resume` плюс `rejected`; обязательные
подтверждения, согласия и отправки записываются отдельно. Разница считается только
для пар, где оба режима достигли правильного результата. Неуспешные и незаконченные
пары перечислены отдельно; отсутствие результата не является экономией.

Основной прогон состоит из 18 попыток и не включает пилот. Даже положительный
результат остаётся ограниченным измерением на трёх случаях с имитацией человека.
