# Новый контроль: 2026-11-03

Небольшой синтетический набор из шести русскоязычных случаев для независимой проверки support-agent. Это целевой контроль требований, а не выборка для оценки качества на потоке обращений. Все имена и адреса электронной почты вымышлены.

Файл: `control-new-2026-11-03.json`.
SHA256: `c2c575510ef16e8c0a6b1ab41c34054e1ab8ee38f61ebb50e9d4a19aaec16800`.
После фиксации хеша файл не изменяется.

Состав: выбор заказа для обмена, недостающая идентификация, отзыв согласия, изменение цены, возврат, передача специалисту. Существенные отличия от прежнего контроля: различение доставленного и отменённого заказов, поиск по имени и индексу вместо электронной почты, отказ от обмена с возвратом разницы, переход от возврата разницы к доплате, возврат на исходную вторую карту, просьба изменить уже оформленный обмен на возврат. Используются разные товары и характеристики; каждый заказ содержит один товар.

Ожидаемые действия ограничены доступными возможностями: создание заявки на обмен или возврат либо локального обращения со статусом `open`. В контракте последнему соответствует `expected.result_status = "ticket created"`. Отзыв согласия сохраняет исходное состояние заказа. Заявка не означает завершённый обмен, возврат товара или перечисление денег.

Обязательные согласие и HITL обеспечивает приложение. Для изменения цены требуется согласие на актуальные условия. Факты профиля, заказа и товара доступны через БД; `expected` и `interactions` не передаются модели. `retained_item_forms` содержит только словоформы товара и цвета, без образцов ответа.

Набор составлен по переданной схеме. Старый `cases.json` прочитан только для проверки отличий. Код агента, оценщик и тесты не читались и не запускались; API и `.env` не использовались. До записи проверены синтаксис JSON, число случаев, уникальность идентификаторов, наличие синтетических имён и допустимость исходных статусов. Результатов прогона нет. После раскрытия набора его нельзя использовать как независимый контроль для последующей настройки.
